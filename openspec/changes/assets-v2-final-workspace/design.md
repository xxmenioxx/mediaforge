## Context

See [proposal.md](proposal.md) for motivation and [specs/assets-workspace/spec.md](specs/assets-workspace/spec.md) for the observable contract. The current Assets route is owned by `AssetsPage`; `AssetsHierarchyPanel` in `AssetsWorkspace.tsx` already renders one presentation tree over separate RAW and Library projections. `SelectedAssetDetail` already receives persisted selected-asset summary data and callbacks for Preview, Assign Profile, and Test Encode. Keep those canonical owners and extend the existing React + MUI workspace.

The prior `assets-v2-workspace`, `assets-v2-raw-library-fidelity`, and `assets-v2-visual-parity` changes are completed planning inputs for Library density, shared RAW/Library navigation, and the unified tree. They remain historical artifacts; this change adds the final column, evidence, action, resize, and selected-workspace contract in a new `assets-workspace` capability because the main OpenSpec spec inventory contains no Assets capability.

The visual references are local working files under `docs/design-reference/assets-v2/figma-make/` and `docs/design-reference/assets-v2/asstesv2.png` (the image's existing filename is misspelled). Use the Figma Make reference for visual hierarchy, compact rows, selected state, toolbar separation, and responsive composition. Use the image for the selected workspace's landscape preview, centered Play overlay, duration badge, identity/context, technical summary, and actions. Keep the workspace compact horizontally on desktop and reflow at narrower widths. Translate those cues into existing MUI components; do not copy the reference app's architecture or dependencies.

The current frontend `Asset` inventory type has persisted technical summaries but no artwork field. A targeted search of the frontend API and backend handlers found no existing artwork or thumbnail contract, and the selected-detail caller does not currently provide either artwork URL. Artwork sources therefore remain conditional on data already exposed by existing supported paths; until one is found and wired, the actual workspace displays the generic placeholder. This design does not assume a new Jellyfin or media-artwork endpoint. A component-level fallback helper accepting test URLs does not constitute integration of Jellyfin or MVForge artwork.

## Goals / Non-Goals

**Goals:**

- Complete one responsive RAW/Library workspace using the current Assets route, inventory, source/library identity, and shared presentation.
- Provide compact mode-specific technical tables, truthful cached Advisor evidence, and separate path and asset action surfaces.
- Make hierarchy resizing accessible and persist its bounded width locally.
- Keep selected deep detail lazy and visually below the table.

**Non-Goals:**

- Add a second Assets page, separate RAW/Library tabs, synthetic inventory roots, API endpoints, dependencies, or backend eligibility rules.
- Change Queue execution, Advisor scoring, profile resolution, Test Encode, validation, Publisher, metadata enrichment, lifecycle models, or media processing.
- Generate artwork, previews, snapshots, or row-level media analysis.

## Decisions

1. **Keep one route and canonical tree over distinct inventory projections.** `AssetsPage` remains the owner of current query, inventory, selection, and mutation state. The shared hierarchy presents the existing RAW source-group/logical-group/path projection and configured Library/path projection as sibling roots. Use their existing identities and context selection to filter the shared inventory surface. Do not add tabs, parallel hierarchy state, or roots for workflow/evidence destinations. This extends the existing `AssetsHierarchyPanel` composition and avoids another context authority. Alternative: duplicate the page by mode or flatten RAW into Library identity; either would create divergent navigation and lose source semantics.

2. **Use mode configuration for the table while keeping row identity shared.** Render the Library and RAW column sets from the same inventory-table surface. Use the existing persisted `Asset` fields and canonical summaries; missing encoder, bitrate, HDR, audio, or other detail remains unavailable rather than prompting per-row enrichment. The Asset cell renders only `fileName`; selected tree and breadcrumb context carries path. Keep all row actions behind one labeled overflow menu, and route each to the existing action owner. Alternative: create separate tables and action hooks; that would repeat behavior and widen the divergence between RAW and Library.

3. **Keep path workflows in their path owner and asset workflows in row/detail owners.** Present path actions, selected asset count, and path context in a compact V2 toolbar adjacent to the table. Replace the legacy `AssetGroupRow`-inside-table presentation while reusing its existing callbacks, mutations, confirmations, and backend behavior; do not duplicate those handlers. RAW exposes supported Scan, explicit Advisor, Queue/Preflight, and Configure Path (which includes existing path-level profile configuration); Library exposes applicable Queue/Preflight and supported move/path operations. The current rename dialog supports Library paths only, so RAW path Rename is an unsupported follow-up and is not added without a canonical action/backend contract. Destructive operations remain separated in an overflow. Row overflow and selected-detail callbacks enter existing asset actions and dialogs. Queue continues through existing preflight/planning and confirmation; the UI does not compute action eligibility independently. Alternative: put every action in each row or create a new generic mutation layer; both obscure scope and risk changing lifecycle behavior.

4. **Treat Advisor as persisted evidence and explicit work.** Use `AdvisorResponse.score` only when the response is already available from an existing cache/result path. Render the score as a compact rating; use a restrained neutral state for not evaluated and a visibly distinct unavailable/off state. A path-level Advisor command remains an explicit user operation that can refresh existing results. Remove any legacy `AssetGroupRow` query that evaluates Advisor on group expansion; never evaluate Advisor during render, expansion, sorting, pagination, or tree selection. The explicit path command must populate the existing cache key `['advisor', 'asset-row', asset.path, profileId]`. Alternative: invoke Advisor per row for richer columns; this violates the inventory performance boundary and makes a browse action perform analysis.

5. **Add resizing as local presentation state.** Keep width in a local preference with a 300px default and 220px/420px bounds. Clamp valid numeric values on restore and use the default if the value is malformed. Expose an accessible vertical separator with keyboard resizing and visible focus while preserving tree focus/selection. At narrow widths, allow the hierarchy and list to stack or reflow; do not let the saved desktop width force page-level overflow. Alternative: persist width in backend user settings or URL state; neither is needed for a local layout preference and both add another state contract.

6. **Extend the existing selected-detail boundary below the table.** Keep `SelectedAssetDetail` below the table and collapsible. Reuse its selected asset, persisted snapshot, and current action callbacks; load deeper persisted detail for the selected asset only. On desktop, keep the composition compact horizontally: landscape artwork with centered Play and duration at left; filename, series/collection/season/path context, and category/library/container/size/resolution/codec quick facts in the center; Estado, Perfil, Subtítulos, Duración, and Modificado as context; video codec, resolution, and audio as technical details; and Assign Profile, Test Encode, and a (...) action menu. Avoid a duplicated prominent status badge when Estado already communicates status. Reflow at narrow widths. Apply Jellyfin → existing MVForge artwork/thumbnail → generic placeholder only when actual supported URLs/sources reach the caller. The current contract exposes none, so the current workspace must use the placeholder; recording the artwork integration gap is the completion behavior for this issue. Do not invent an endpoint or generate artwork. Alternative: per-row image requests or media generation; those create unbounded work and are explicitly out of scope.

7. **Preserve status and eligibility authority.** Map RAW labels from canonical source, review, profile, and lifecycle/Queue evidence already available. Do not derive a new lifecycle state from missing data or UI inference. For actions whose eligibility is not present in the current inventory response, preserve the existing backend check, preflight, and disabled-reason behavior rather than adding row-specific checks. Alternative: infer `Ready for Queue` from absence of errors or asset status alone; that can disagree with backend policy.

8. **Verify observable behavior through focused UI regressions.** Add tests for mode/context rendering, exact column sets and filename-only cells, cached/missing/off Advisor states without render or expand evaluation, explicit path Advisor cache population, compact row menu actions by mode and their existing routes, path-toolbar behavior, hierarchy width restoration/range/keyboard operation, selected-detail composition/placement/collapse, and placeholder behavior while no supported artwork URL is wired. Do not assert Jellyfin/MVForge fallback as implemented until a supported source exists. Verify action eligibility, responsive accessibility, and bounded requests. Then run the requested frontend lint/build, strict OpenSpec validation, and canonical repository verifier. Tests should assert roles, labels, column content/order, state, requests, and keyboard behavior rather than screenshot-specific pixel coordinates. Do not mark parity tasks complete until these observable behaviors are covered.

## Risks / Trade-offs

- [Some technical or Advisor evidence is absent from current inventory responses] → Show unavailable/not-evaluated values and retain selected-only detail loading; do not add per-row analysis.
- [Jellyfin artwork and MVForge thumbnail sources are not exposed in the inspected current Asset/API contract and are not wired by the selected-detail caller] → Keep the generic placeholder; the fallback order is conditional behavior for a future supported source and artwork integration remains a follow-up.
- [RAW path Rename has no existing supported dialog/action contract; current path Rename requires a Library scope] → Keep RAW Rename out of the toolbar and retain it as a follow-up if a canonical RAW path operation becomes available.
- [The legacy path action owner may combine presentation and behavior] → Extract the compact V2 toolbar presentation while retaining its existing handlers; remove any render/expand-triggered Advisor request without changing explicit workflow semantics.
- [Local width storage can be stale or malformed] → Clamp supported numeric widths, fall back to 300px on unreadable state, and keep keyboard resizing available.
- [Dense columns may exceed a narrow viewport] → Keep table scrolling local to the inventory region, reflow the hierarchy and selected workspace, and retain page-level width constraints.
- [The Figma Make reference may depict workflow behavior outside existing capability contracts] → Treat it as visual guidance only and keep unsupported actions out of the product flow.

## Migration Plan

No server-side data migration or API rollout is planned. Store only the bounded hierarchy width as a local presentation preference. Keep the existing Assets route, inventory query contracts, context identity, and action owners. Reverting the frontend change removes the local preference use and restores the prior workspace without changing media or lifecycle data.
